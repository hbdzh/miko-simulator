# 多设备管理

在设备中心的「全部设备」中勾选设备，可批量启动、停止、安装 APK 或克隆。启动间隔按开始请求的时间计算；每台设备独立显示进度和结果，失败或取消后可单台重试。

批量任务最多同时处理两台设备；克隆逐台执行。取消会阻止排队项目启动，并向正在运行的任务发送取消请求。克隆取消时会停止复制并清理未完成的副本；如果清理失败，界面显示失败和原因。

停止设备时，取消可中断准备阶段；正在保存的快照会先保存完毕，再取消停止并保持设备运行。进入最终关机后会完成关机并报告实际结果。安装 APK 时先将文件暂存到设备；取消暂存会停止传输并清理临时文件。进入 Android 的安装提交阶段后，会等待安装结果并报告成功或失败；若设备连接中断导致结果不明，界面会提示先检查应用状态并显示保留的临时文件路径，避免打断可能仍在进行的安装。临时文件清理失败也会显示具体结果与路径。

批量克隆为每台已停止的源设备创建一个独立副本，自动生成不重复的名称。普通克隆不保留快照；复制前按需要复制的文件逻辑大小预留空间，并保留 1 GiB 余量。这个检查按完整复制估算，因此即使文件系统支持写时复制，可用空间不足时也可能拒绝克隆。

分组在「全部设备」创建，可用当前选择创建分组，随后添加或移除所选设备、重命名或删除分组。组信息存放在 miko 数据目录的 `device-groups.json`，不更改 Android SDK 或 AVD 目录；删除分组不会删除设备。筛选和搜索可组合使用，多选在切换筛选时保留。

「排列窗口」按各窗口所在的显示器分别排列已打开的播放器，使用该显示器可见区域并保持设备画面比例。全屏窗口和因屏幕空间不足无法放入网格的窗口会跳过并提示；可以退出全屏或减少同一屏幕的窗口后重试。
## 多开资源策略

「全部设备」显示共享内存预算和每台设备的运行状态。展开设备占用可查看模拟器进程树最近一次 CPU 和内存采样，以及计入预算的数值；后者取预估值与最近测量值中的较大者。采样约每 30 秒更新，CPU 100% 约为一个逻辑核心；启动初期或采样失败时可能尚无测量值。运行中的设备可从这里休眠或停止。

后台画面可选择「保持实时画面」或「后台节省资源」（默认）。节省资源时，非当前活动窗口的可见画面最多更新 5 帧/秒，隐藏的窗口暂停画面更新；切回前台后恢复正常帧率。该设置只减少播放器接收画面后的分配和渲染开销，模拟器本身仍按原有方式运行，脚本回放和同步输入不受此设置控制。「保持实时画面」会继续处理隐藏和后台窗口画面，因此可能增加播放器资源消耗。

创建多台设备时可考虑 `agent-lean` 方案（720 × 1280、2 核、2 GB 内存，音频和摄像头关闭）；建议不会自动修改已有设备。具体资源占用取决于运行的应用和主机环境。
